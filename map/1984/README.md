# 1984

The square at sixpack.wtf keeps a mint book in the page ledger. Cap 0 there means the book has no maximum. A later mint of the same name is allowed. Those lines are receipts in the book. They are not Kaspa transactions, and they are not this covenant.

This token has a hard allowance of 20,280,000 and a per-mint limit of 4,056. Five thousand addresses finish it. The square can show a covenant holder list only after a broadcast exists, and the list has to be paged. Five thousand addresses on one card will stall the page.

Key the square row on the covenant id together with the extension. The name string is not enough. Path `launch::stp-trump2028` and path `launch::stp-trump2028-last-call` share the name digest and are two families. The first family is the 7 Oct submit. Its key is gone. The second is the plan in [TOKENOMICS.md](../../TOKENOMICS.md).

This mint sets borrow scheme `0x00`. The square should not offer a borrowed-receive button for it. Owner scheme `0x00` stores the public key, so a holder lookup that hashes the key will miss these outputs.

The square's miner fee is 87 times the ordinary Testnet-10 rate. That rate is for the page. Copying it onto these covenant transactions would crowd the node. The mint prompts pay the node's ordinary estimate.
